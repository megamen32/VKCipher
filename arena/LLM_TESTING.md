# LLM и обновление тестов

## Ограничения

Arena не отключает safety-фильтры модели и не пытается обходить блокировки.
Для LLM smoke-тестов используйте нейтральные placeholder-ы (`[TOPIC_A]`,
`[ACTION_B]`, `[OBJECT_C]`) вместо чувствительных терминов или описаний.
API-ключ не записывается в репозиторий, логи и fixtures.

## Переменные окружения

Используйте OpenAI-compatible endpoint только через переменные окружения:

```bash
export LLM_BASE_URL="https://llm.bezrabotnyi.com/v1"
export LLM_MODELS="gemma4,qwen3.5"
export LLM_API_KEY="..."
```

Не добавляйте эти значения в `.js`, `.json`, `.env`, Playwright trace или
commit. Если endpoint недоступен или отвечает ошибкой, smoke-тест должен
завершаться понятной ошибкой, а обычные локальные тесты должны продолжать
работать без LLM.

Production-словарь не генерируется моделью. Его исходники скачиваются один раз
и собираются детерминированно:

```bash
npm run dictionary:build
```

Модель можно использовать только как дополнительный audit уже существующих
слов. Полная разметка запускается так:

```bash
node arena/classify-dictionary.js --batch-size=1024 --concurrency=1
```

Результат сохраняется в `arena/artifacts/dictionary-safety.json` и исключён
из git. Оркестратор запускает модели для каждого batch параллельно и применяет
консервативное правило: `safe` только при согласии всех моделей; `borderline`
или `unsafe` любой модели побеждает. В artifact сохраняются решения каждой
модели и итог. Это мнение выбранных моделей, а не универсальная гарантия для
всех антиспам- и moderation-систем.

## Исторический итеративный audit

Этот режим сохранён для воспроизводимости предыдущего эксперимента. Он умеет
запрашивать новые кандидаты у LLM, поэтому его результат нельзя автоматически
публиковать в `extension/dictionaries` и нельзя считать production-источником.

Для цикла `критика -> новые кандидаты -> критика только новых -> финальный полный проход`
используйте отдельный orchestrator:

```bash
node arena/iterate-dictionary.js \
  --input=extension/dictionaries/ru-common-8192-v4.txt \
  --target=8192 \
  --oversample=2 \
  --max-rounds=100 \
  --new-per-model=128 \
  --batch-size=256 \
  --concurrency=1 \
  --output=arena/artifacts/dictionary-safety-iterative.json
```

Сбор продолжается до получения `target * oversample` уникальных кандидатов;
`--max-rounds` является только аварийным предохранителем. Затем финальный проход оставляет
из этого пула только safe-слова и выбирает первые `target` слов. Каждый раунд отправляет
критикам только слова, которых нет в checkpoint. После критики
модели предлагают новые короткие кириллические слова; уже виденные слова удаляются, а
denylist отбрасывается до следующего запроса. В конце весь собранный safe-набор проверяется
заново всеми моделями. `--interactive` ставит паузу после каждого раунда, `--resume`
продолжает незавершённый checkpoint.

Остановка возможна по достижению цели, отсутствию новых кандидатов или лимиту раундов.
Результат требует ручной проверки перед публикацией: он не отключает фильтры и не является
гарантией обхода антиспам- или moderation-систем.

## Как обновлять corpus

1. Добавьте короткие нейтральные сообщения в `arena/corpus/messages.js`.
2. Для обычных сообщений используйте `normalMessages`, для защищённых
   plaintext-сообщений -- `secretMessages`.
3. Не добавляйте в corpus реальные секреты, токены, персональные данные или
   инструкции для причинения вреда.
4. Если сообщение содержит emoji, проверяйте и code points, и UTF-16 units:
   пара surrogate units считается как две единицы лимита VK.
5. После изменения corpus запускайте весь набор проверок:

```bash
npm run build
node --check extension/vkencrypt.user.js
npm test -- --reporter=line
npm run arena -- --rounds=256
npm run test:arena
git diff --check
```

## Как добавлять regression-тест

- Криптографию и кодеки добавляйте в `tests/playwright/crypto.spec.js`.
- DOM, composer, авторасшифровку и ошибки добавляйте в
  `tests/playwright/userscript.spec.js`.
- Media и cross-origin поведение добавляйте в
  `tests/playwright/media.spec.js`.
- Ограничения VK и adversarial cases добавляйте в
  `tests/playwright/adversarial-arena.spec.js`.
- Для каждого найденного бага сначала добавьте минимальный падающий тест,
  затем исправление, затем повторите полный набор команд выше.
- Не используйте реальный VK в обычном CI-тесте: live-проверка запускается
  отдельно через `RUN_LIVE=1 npm run test:live`.
